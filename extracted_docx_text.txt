4. Key Business Logic Notes for Backend
Price calculation is always server-side. POST /bookings/estimate-price must be called before showing any final number to the customer — never trust a price sent from the Flutter app.
Double-booking protection is enforced at the database layer (UNIQUE(vehicle_id, booking_date, start_time)), not just in application code.
Availability calendar (vehicle_availability or the derived equivalent) must be checked before allowing a date selection on the Car Details screen — this happens before route/price, so it’s a separate, earlier read.
Role routing after login is server-determined — the JWT payload from /auth/otp/verify carries role, and Flutter uses that (not a button the user picks) to decide which home screen to show.
Reviews are blind until both sides submit or 48 hours pass (visible_at field) — don’t expose one side’s review via the API until this condition is met.
